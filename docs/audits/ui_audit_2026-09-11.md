## 3. Bug & Defect Catalog

### Defect 1 (CRITICAL / HIGH): Dashboard Typed Commands Dropped When Voice Session Dormant
- **Location**: `app/monitors.py:157-174` (Foreign Code - READ ONLY for this stream)
- **Severity**: High / Functional Disconnect
- **Description**: In `_process_dashboard_commands()`, the entire command handling block is wrapped inside `if self.session:`. If the Gemini Live voice session is not yet established, is reconnecting, or has encountered an API quota limit, any command typed in the dashboard (including `/toggle_mic`, `/user`, `/agent`, `/research`, or chat requests) is dropped with `print("[Dashboard] Dropped item (no session)")`. Furthermore, even when `self.session` is active, non-mic text commands are sent directly to `session.send_client_content()` rather than being routed through `self._on_text_command(clean_text)`.
- **Impact**: Users cannot execute slash commands or mute the mic from the web dashboard unless the Gemini voice socket is live, and slash commands bypass the orchestrator router.
- **Evidence**: Confirmed in Checklist A and Checklist E (`E_visibility/E_results.log`).
- **Proposed Fix for Main Chat**:
  In `app/monitors.py:154`, move the text command parsing outside `if self.session:` and route commands through `self._on_text_command(text)`:
  ```python
  text = str(item).strip()
  if text:
      if self._on_text_command(text):
          continue
      if self.session:
          await self.session.send_client_content(...)
      else:
          self.ui.write_log(f"SYS: Voice session offline — cannot send text: '{text[:40]}'")
  ```

### Defect 2 (HIGH): Empty `event_type` in Kernel Dashboard Bridge
- **Location**: `kernel/proactive/dashboard_bridge.py:95, 134` (Foreign Code - READ ONLY for this stream)
- **Severity**: High / Event Telemetry Corruption
- **Description**: In `_on_tool_event` and `_on_job_event`, the bridge accesses `getattr(event, "segment", "")`. However, `kernel.types.Event` defines `type: str`, not `segment`. Consequently, `segment` evaluates to `""`, and the bridge broadcasts `{"type": "kernel_event", "event_type": ""}` over the WebSocket.
- **Impact**: Dashboard clients expecting `m.event_type.startsWith("tool.")` or `job.` fail to categorize kernel events properly.
- **Mitigation Implemented in Owned Files**: In `dashboard/static/app.html`, updated `receive(m)` to fall back to `m.tool` and `m.job_id` when `m.event_type` is empty.
- **Proposed Fix for Main Chat**:
  In `kernel/proactive/dashboard_bridge.py`, change:
  ```python
  segment = getattr(event, "type", getattr(event, "segment", ""))
  ```

### Defect 3 (MEDIUM): Thread-Safety Violation in UI Mute Toggle (FIXED)
- **Location**: `ui.py:633` (Owned File - Fixed in `pUI-audit`)
- **Severity**: Medium / Runtime Abort
- **Description**: In `UltronWebWindow._toggle_mute()`, `self._on_state(state)` was called directly. When `ui.muted` was toggled from `_process_dashboard_commands()` on the asyncio background thread, it called `_eval_js()` off the Qt main thread, violating Chromium's UI thread assertion and causing immediate process termination.
- **Fix Implemented**: Routed mute state changes through the existing queued signal: `self._state_sig.emit(state)`.

### Defect 4 (MEDIUM): Unhandled `JSONDecodeError` on Malformed WebSocket Messages (FIXED)
- **Location**: `dashboard/server.py:593` (Owned File - Fixed in `pUI-audit`)
- **Severity**: Medium / DoS Vulnerability
- **Description**: `await websocket.receive_json()` in `ws_ep` was not protected by a JSON decode error handler. Sending non-JSON text caused an unhandled ASGI exception that closed the connection.
- **Fix Implemented**: Wrapped `receive_json()` in a `try...except (json.JSONDecodeError, ValueError): continue` block.

### Defect 5 (LOW / FEATURE GAP): Missing Phone Mic Audio Client Implementation
- **Location**: `dashboard/static/app.html`
- **Severity**: Low / Feature Incomplete
- **Description**: While `dashboard/server.py` defines `/ws/phone-audio` to relay mic packets into `_phone_audio_queue`, `app.html` contains no JavaScript code using `navigator.mediaDevices.getUserMedia` or AudioWorklet to capture and transmit audio.
